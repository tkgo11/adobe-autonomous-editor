# Workflow: Tutorial / Screencast / Software Demo

## Trigger

Use for screen recordings, software tutorials, coding demos, app walkthroughs, course lessons, slide-led explanations, and product demonstrations.

## Default assumptions

- instructional clarity outranks cinematic style;
- cursor/UI/text must remain legible;
- remove waiting/loading/typing dead time unless educationally relevant;
- zoom/crop only to direct attention, never so aggressively that interface context is lost.

## Analysis priorities

- OCR/UI regions and text legibility;
- cursor position and click events where detectable;
- narrated step boundaries;
- loading/waiting periods;
- mistakes and retries;
- sensitive/private screen content that may need masking;
- mismatches between narration and visible UI state.

## Edit plan

1. Align narration and screen actions.
2. Remove dead wait time and failed attempts while preserving causal continuity.
3. Add focused zooms/highlights around important controls.
4. Add labels/arrows/callouts only when they improve comprehension.
5. Keep enough pre/post-roll around actions so viewers can follow them.
6. Insert chapter/step cards for longer tutorials.
7. Mask sensitive data when required by the brief or obvious context.

## Premiere rules

- preserve source resolution when possible for readable UI;
- use transform/nest techniques that avoid repeated resampling;
- keep cursor movement natural around cuts;
- use freeze frames sparingly for explanation pauses.

## After Effects escalation

Use AE for:

- tracked callouts;
- magnifiers;
- animated cursor emphasis;
- UI replacement/mockups;
- complex masking/redaction;
- diagram overlays.

## QC gates

Reject and repair if:

- important text is unreadable at final delivery resolution;
- a cut skips a required action and makes the procedure impossible to follow;
- narration describes a different UI state than shown;
- zooms hide necessary interface context;
- private/sensitive content intended for masking remains visible.
